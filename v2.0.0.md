# Veltix 2.0.0 : API refined, core stabilized

> The first major release of Veltix. A redesigned protocol, a high-level API that
> finally feels natural, and a thread-safe core built for production.

Veltix 2.0.0 is the culmination of everything learned from the v1.x series. The wire protocol is now smaller and
extensible, the API removes much of the boilerplate you used to write by hand, and the internals have been hardened for
real concurrent workloads.

Zero dependencies. Zero compromise.

## Highlights

### Compact wire protocol

The protocol header has been redesigned to reduce overhead, simplify request tracking, and prepare the protocol for
future extensions like compression and encryption.

Request IDs are now 16-bit integers allocated automatically by a thread-safe
`IDAllocator`, replacing random 4-byte identifiers. On the server side,
`ClientAllocator` assigns each client a unique ID window, ensuring globally unique request IDs without any cross-client
coordination.

### High-level API

The most common operations now require significantly less boilerplate.

`Request` now accepts `text` and `json` payloads directly:

```python
Request(MY_TYPE, text="hello")
Request(MY_TYPE, json={"key": "value"})
```

`Response` decodes content lazily:

```python
response.text  # UTF-8 string
response.json  # parsed dict
response.is_text  # bool, no exception
response.is_json  # bool, no exception
```

Convenience methods on `Server` and `Client`:

```python
server.send(request, client)  # no need to access server.sender
server.broadcast(request)  # broadcast to all clients
client.send(request)  # same pattern
```

### Thread safety hardened

The networking core has been hardened against race conditions across the server, client, and handshake layers.

`Server.running` now uses `threading.Event` instead of a bare `bool`, while shared state such as `is_connected`,
`_fail_count`, `_started`, `_closed`, and
`handshake_done` is protected by proper synchronization primitives.

### Logger migrated to stdlib

The internal logger now wraps Python's `logging.Logger("veltix")` with
`StreamHandler` and optional `RotatingFileHandler`. The public API is unchanged, but you get standard log formatting,
file rotation, and seamless integration with the Python logging ecosystem.

### Better developer experience

The project now uses a modern `src` layout, Hatch as its build backend, Google-style documentation throughout the
codebase, automated publishing, and improved test coverage across critical networking components.

## What changed

A summary of every user-facing change in v2.0.0, grouped by theme.

### Wire protocol

The binary framing has been redesigned to reduce header size, simplify request tracking, and prepare the protocol for
future extensions.

**Header layout changed:**

| Field      | v1.x             | v2.0.0               |
|------------|------------------|----------------------|
| MAGIC      | 2 bytes          | 2 bytes              |
| flags      | *new*            | 1 byte               |
| code       | 2 bytes          | 2 bytes              |
| size       | 4 bytes          | 4 bytes              |
| CRC        | 4 bytes          | 4 bytes              |
| request_id | 4 bytes (random) | 2 bytes (sequential) |
| **Total**  | **16 bytes**     | **15 bytes**         |

The new flags byte is reserved for future use (compression, encryption). Currently always `0x00`.

**Request IDs are auto-allocated.** You no longer need to generate or manage IDs.
`Sender.send()` assigns one automatically via `IDAllocator`. Each client gets a unique ID window from the server during
handshake, so IDs are globally unique across all connections without any central coordination.

### Request and Response

**Request accepts text and JSON payloads.** No more manual `.encode()` or `json.dumps()`.

```python
req = Request(MY_TYPE, text="hello")
req = Request(MY_TYPE, json={"key": "value"})
```

Exactly one payload argument is required (`content`, `text`, or `json`).

**Response decodes content lazily.** Properties are cached after first access, so there's no performance penalty for
checking multiple times.

```python
text = response.text  # cached, raises InvalidContentError on failure
data = response.json  # cached, raises InvalidContentError on failure
is_text = response.is_text  # bool, safe check
is_json = response.is_json  # bool, safe check
```

**`Request.respond(response)` copies the request ID** for request/response correlation, making RPC patterns much
cleaner:

```python
@server.route(ECHO)
def on_echo(client: ClientInfo, response: Response) -> None:
    req = Request(ECHO, response.content)
    req.respond(response)  # copies request_id for correlation
    server.send(req, client)
```

### Server

**New convenience methods** that accept `ClientInfo` directly, no need to reach into `server.sender`:

```python
server.send(request, client)  # send to one client
server.broadcast(request)  # broadcast to all
server.broadcast(request, except_clients=[c])  # exclude specific clients
server.wait_until_closed()  # block until close_all()
server.restart()  # stop + start, preserves routes
```

**`server.sender`** is now a property (no more `get_sender()`).

**`ServerConfig.id_window`** controls the unique ID window size per direction (default: 30000). This is sent to clients
during the handshake.

### Client

Same convenience pattern as the server:

```python
client.send(request)
client.send_and_wait(request, timeout=5.0)
client.wait_until_closed()
```

**`client.sender`** is now a property (no more `get_sender()`).

### Handshake

The handshake now exchanges version and metadata as JSON over the raw TCP stream before any Veltix framing:

```
Server -> Client: {"v": "2.0.0", "meta": {"id_window": 30000}}
Client -> Server: {"v": "2.0.0", "meta": {}}
Server -> Client: {"result": "ok"}
```

The client reads `meta.id_window` and uses it to configure its `IDAllocator`.

### Logger

The logger is now backed by Python's standard `logging` module. The public API is unchanged:

```python
logger = Logger.get_instance()
logger.info("Server started")
```

But you now get standard formatting, `RotatingFileHandler` support, and compatibility with the entire Python logging
ecosystem.

`LoggerConfig` lost two fields: `async_write` and `buffer_size` (they were dead code). Two fields became functional:
`show_timestamp` and `show_level`.

## Migration guide

If you're upgrading from v1.x, here's what you need to change in your code. Each item shows the old and new way side by
side.

### `generate_random_id()` removed

Request IDs are now allocated automatically by `IDAllocator`. You don't need to generate or manage them.

```python
# v1.x
from veltix import generate_random_id

req = Request(MY_TYPE, b"data", request_id=generate_random_id())

# v2.0.0
req = Request(MY_TYPE, b"data")  # ID assigned automatically
```

### `get_sender()` removed

Use `server.sender` and `client.sender` properties instead.

```python
# v1.x
server.get_sender().send(request, client)
client.get_sender().send(request)

# v2.0.0
server.send(request, client)
client.send(request)
```

### `Response.request_id` is now `int`

Was 4 bytes (`bytes`), now 2 bytes (`int`). This affects request/response correlation.

```python
# v1.x
req = Request(ECHO, b"data", request_id=response.request_id)

# v2.0.0
req = Request(ECHO, b"data")
req.respond(response)  # copies request_id automatically
```

### `Response._hash` is now private

If you were accessing `response.hash`, it's now `response._hash`. This was never part of the public API.

### `ERROR` and `INVALID_REQUEST` system types removed

Only `PING` and `PONG` remain as system types. If you were using `MessageType(20)` or `MessageType(21)`, define your own
types instead.

```python
# v1.x
from veltix import ERROR, INVALID_REQUEST

# v2.0.0
MY_ERROR = MessageType("my_error")  # define your own
```

### `SocketEvents` enum removed

This was unused since v1.9.0 and has been deleted. Use `VeltixBus` events instead.

```python
# v1.x
from veltix.socket_core.base_socket import SocketEvents

# v2.0.0
from veltix.internal.events import ServerEvent, ClientEvent

server.bus.subscribe(ServerEvent.ON_CONNECT, callback)
```

### `LoggerConfig` fields removed

`async_write` and `buffer_size` no longer exist. If you were passing them, just remove them.

```python
# v1.x
LoggerConfig(async_write=True, buffer_size=200)

# v2.0.0
LoggerConfig()
```

### `broadcast()` now accepts `ClientInfo`

In v1.x, `broadcast()` accepted `BaseSocket` objects. In v2.0.0, it accepts both `ClientInfo` and `BaseSocket`.

```python
# v1.x
server.broadcast(request, except_clients=[client.conn])

# v2.0.0
server.broadcast(request, except_clients=[client])  # ClientInfo works directly
```

### Handshake protocol changed

If you were implementing a custom handshake or parsing the handshake bytes, the format has changed completely. The
handshake now exchanges JSON payloads before any Veltix framing is used.

```python
# v1.x
# Binary HELLO/HELLO_ACK messages

# v2.0.0
# JSON over raw TCP:
# Server -> Client: {"v": "2.0.0", "meta": {"id_window": 30000}}
# Client -> Server: {"v": "2.0.0", "meta": {}}
# Server -> Client: {"result": "ok"}
```

## Performance

Several internal changes improve throughput and reduce overhead compared to v1.x.

- **15-byte protocol header** : 1 byte smaller, fewer bytes on the wire per message
- **Sequential request IDs** : `IDAllocator` uses a monotonic counter instead of random generation, eliminating
  allocation overhead
- **Logger hot path optimized** : removed `inspect.currentframe()` from every bus log call, restoring v1.9.0-level
  latency (~0.03ms per message)
- **Reduced allocations** : `Sender` reuses internal structures instead of creating new objects per send

## Quality

Veltix 2.0 ships with more than 560 automated tests covering protocol parsing, handshakes, reconnection, threading,
request/response handling, and logging. Critical networking components now reach 100% coverage.

The full test suite runs in under 10 seconds via `pytest-xdist`, with both `THREADING` and `ASYNC` socket backends
tested in parallel.

## What next

Veltix will never try to be the fastest framework, the most feature-rich, or a solution for every use case. That's not
the point.

The goal is simpler: make networking something you don't think about. Not a wall you hit, not a layer of complexity you
have to manage : just a tool that works, the way file I/O or threading works in Python.

That means continuing to remove friction. Cleaner APIs, smarter defaults, better error messages. If something can be
automated, it should be. If something can be invisible, it should be.

## Looking ahead

Veltix 2.0 establishes a stable foundation for the next generation of the library. With the protocol, threading model,
and public API now settled, future releases can focus on new capabilities rather than architectural changes.

Thank you to everyone who tested the beta releases and helped shape this major update.
